# Chong Die Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fork Owlbear Rodeo's dice extension into ChongKit as "Chong Die", adding an Avrae-style `!r` command line, a panel of tabs and saved-roll pills (Place or Instant per tab), and follow-up dice waves for rerolls and explosions.

**Architecture:** Upstream source is copied into `chong-die-src/` and built by Vite into the committed `chong-die/` folder. A pure TypeScript roll engine (`src/roll/`) parses commands and evaluates them against landed die values, returning either the next wave of dice to throw or the final result. React code in `src/chong/` holds the command line, panel and saved-rolls store, and a runner that feeds engine waves into the upstream roll store.

**Tech Stack:** TypeScript 4.6, React 18, MUI 5, zustand, three.js / Rapier (upstream), Vite 3, Vitest 0.34, Owlbear Rodeo SDK.

**Spec:** `docs/superpowers/specs/2026-10-06-chong-die-design.md`

## Review Focus

3. **Place, then the player changes dice by hand with the upstream picker:** the placed command must be dropped and a normal upstream roll happen. Test in Task 7 (`clearPlaced` on any manual count change).

5. **d10 face `0` and the d100 + d10 pair (`00` + `0` = 100):** logical values must match upstream (`0` → 10 alone; pair sums, `0`+`0` → 100). Test in Task 3 (`readLogical`).

### Task 2: Command parser (`src/roll/parse.ts`)

**Files:**
- Create: `chong-die-src/src/roll/types.ts`, `chong-die-src/src/roll/parse.ts`
- Test: `chong-die-src/src/roll/parse.test.ts`

**Interfaces:**
- Produces (types.ts):
  ```ts
  export type Selector = { kind: "h" | "l" | ">" | "<" | "="; n: number };
  export type Op =
    | { op: "k" | "p" | "rr" | "ro" | "ra" | "e"; sel: Selector }
    | { op: "mi" | "ma"; n: number };
  export type Expr =
    | { t: "num"; value: number }
    | { t: "dice"; count: number; size: number; ops: Op[]; label?: string; id: number }
    | { t: "bin"; op: "+" | "-" | "*" | "/" | "//" | "%"; left: Expr; right: Expr }
    | { t: "neg"; expr: Expr }
    | { t: "paren"; expr: Expr; label?: string };
  export interface Command { kind: "r" | "rr" | "rrr"; times: number; expr: Expr; source: string; dc?: number; comment?: string }
  export class RollError extends Error {}
  ```
- Produces (parse.ts): `parseCommand(input: string): Command` — throws `RollError`.

Rules: leading `!r`, `!rr`, `!rrr` optional (bare → `r`); `!rr N expr`, `!rrr N expr DC`. `d%` = d100; `dX!` = `e` with `sel {kind:"=", n:X}`. Literal selector `k3` = `{kind:"=",n:3}`; `kh3`/`kl1`/`k>10`/`p<3`. `adv`/`dis` as a standalone word anywhere in the comment region turns the first `1d20`/`d20` term into `2d20` with `k h1`/`k l1` prepended to its ops (removed from comment). Spaces allowed between tokens; the expression is the longest valid prefix; the rest (trimmed) is the comment. Dice `id` = order of appearance from 0. `source` = the expression text as typed (trimmed). Limits from Global Constraints → `RollError` with these messages: `"Unknown die d0"`, `"Dice can't have more than 1000 sides"`, `"Repeat count must be 1–25"`, `"Expected a number after kh"` (pattern: `Expected a number after <op><sel>`), `"Missing )"`, `"Nothing to roll"`, `"!rrr needs a DC"`.

### Task 3: Evaluator and physical dice mapping (`evaluate.ts`, `physical.ts`)

**Files:**
- Create: `chong-die-src/src/roll/evaluate.ts`, `chong-die-src/src/roll/physical.ts`
- Test: `chong-die-src/src/roll/evaluate.test.ts`, `chong-die-src/src/roll/physical.test.ts`

**Interfaces:**
- Consumes: `Command`, `Expr`, `Op` from Task 2.
- Produces:
  ```ts
  // evaluate.ts
  export interface LogicalDie { key: string; size: number; parent?: string; reason: "roll" | "reroll" | "explode" }
  export interface DieResult { key: string; size: number; value: number; dropped: boolean; exploded: boolean; rerolled: boolean }
  export interface RepResult { total: number; terms: Map<number, DieResult[]>; success?: boolean }  // terms keyed by dice id
  export interface CommandResult { command: Command; reps: RepResult[]; capped: boolean }
  export interface Evaluation { needed: LogicalDie[]; result: CommandResult | null }
  export function evaluate(cmd: Command, values: Record<string, number>): Evaluation;
  // physical.ts
  export type PhysicalType = "D4" | "D6" | "D8" | "D10" | "D12" | "D20" | "D100";
  export function toPhysical(size: number): PhysicalType[] | null;   // null = virtual
  export function readLogical(size: number, raw: number[]): number;
  export function rollVirtual(size: number): number;                  // crypto.getRandomValues, 1..size
  ```

Keys: wave-1 die `${rep}.${diceId}.${i}`; follow-up `${parentKey}${"r"|"e"}` (a reroll of a reroll appends again: `0.0.0rr`). `evaluate` is pure and deterministic: given values, it walks each rep's tree, applies each dice term's ops in written order, and when an op needs a die whose key has no value, adds it to `needed` and pauses that term (other terms continue). `result` is non-null only when `needed` is empty. Op semantics (Avrae d20): `k`/`p` act on currently kept dice; `h`/`l` pick highest/lowest n among kept; `rr` rerolls matching kept dice until none match; `ro` rerolls each matching kept die once; `ra` rerolls the first matching kept die once and keeps both; `e` adds a die for each matching die, new dice can explode too; `mi`/`ma` clamp kept values. A rerolled die is marked `dropped` + `rerolled`. More than 20 follow-up dice across the command → stop issuing, `capped: true`, evaluate with what exists. `/` is true division, `//` floor, `%` remainder. `!rrr` success = `total >= dc`.

`toPhysical`: 2→`["D4"]`, 3→`["D6"]`, 4/6/8/10/12/20→same, 100→`["D100","D10"]`, else `null`. `readLogical`: d2/d3 `ceil(raw/2)`; d10 `0`→10; d100 pair: `raw[0]+raw[1]`, both 0 → 100; others raw[0].
